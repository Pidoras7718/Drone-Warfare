# DECISIONS.md

Файл фиксирует принятые решения и причины, чтобы через полгода не пришлось вспоминать "почему так".

## Урон дрона реализован через Summon Damage + взрыв, а не через touch damage
Дрон не наносит урон простым касанием (`Projectile.friendly` выключен в обычном полёте). Урон включается только в момент взрыва: hitbox временно расширяется до радиуса взрыва, projectile становится `friendly`, применяется `ExplosionDamage = 80`, вызывается `Projectile.Damage()`. Это должно соответствовать логике "урон от подрыва", а не "урон от касания".

## Friendly Fire / урон по игрокам и мирным NPC пока не включён
Взрыв сделан как friendly projectile damage — то есть в первую очередь работает по враждебным NPC. Урон по игрокам, союзникам и town NPC решено вынести в отдельную систему (`DroneDamageSystem` / config), потому что там нужно отдельно решить:
- должен ли дрон бить владельца;
- должен ли он бить союзников;
- как учитывать PvP;
- как вести себя в мультиплеере;
- должен ли урон по town NPC быть всегда включён или только через config.

## Столкновение с блоками вызывает подрыв
Дрон больше не пролетает сквозь тайлы — при столкновении подрывается. При этом разрушение блоков вокруг точки взрыва ограничено небольшим радиусом, а важные и dungeon-тайлы пропускаются, чтобы не ломать структуры/подземелья случайно.

## Переход с ChatGPT Codex на связку VS Code + Cline + DeepSeek API
Причина: лимит Codex обновляется раз в месяц, что тормозит разработку проекта такого масштаба (десятки классов, физика, мультиплеер, HUD, автопилот, ГНСС, ПВО). Codex лучше держит архитектуру и умеет работать с GitHub "из коробки", но месячные лимиты — узкое место. Решено:
- DeepSeek V4 Flash — для рутинных задач (Item, Projectile, UI, Config, NetworkPacket) — дешевле и быстрее.
- DeepSeek V4 Pro — для архитектурных задач (автопилот, ГНСС, физика, мультиплеер) — качество ближе к GPT.
- Сам DeepSeek API не умеет работать с GitHub/проектом напрямую, поэтому используется агент-оболочка (Cline или Roo Code), который читает проект, меняет файлы, показывает diff и предлагает commit — получается практически аналог Codex, но без месячных лимитов.
- Тариф Go для ChatGPT признан недостаточным для проекта такого масштаба (рассчитан на пробу возможностей Codex, а не на длительную разработку); Plus — оптимален, если понадобится вернуться к Codex.

## Роли в разработке
- Чат с ассистентом — обсуждение архитектуры, механик, алгоритмов и принятие решений, разбор кода при необходимости.
- DeepSeek (через агента) — непосредственное написание кода и внесение изменений в проект.

## Структура "мозга проекта" в Docs/
Решено вести не просто документацию, а живые файлы контекста, которые агент читает перед началом любой задачи: `AI_CONTEXT.md`, `PROJECT_STATE.md`, `DECISIONS.md`, `TODO.md`. Это снижает риск того, что модель забудет архитектурные решения, задублирует код или нарушит структуру — особенно важно при переключении между разными моделями (DeepSeek/Codex/другие).

## Стратегия веток (предложена, не факт что уже применена)
Предложено отойти от единственной ветки `codex/-terraria` в пользу схемы `main` (стабильная версия) / `develop` (текущая разработка) / `feature/*` (например `feature/fpv-drone`, `feature/networking`, `feature/gnss-guidance`) для более безопасного тестирования и параллельной работы над фичами.

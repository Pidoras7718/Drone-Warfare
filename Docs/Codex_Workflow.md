# Как работать над Drone Warfare в Codex

## Что это за среда

Codex Cloud — это рабочая среда для разработки кода в репозитории. В отличие от обычного чата, здесь можно работать с настоящими файлами проекта, Git-историей и pull request'ами.

Для Drone Warfare это удобнее обычного чата, потому что мод быстро вырастет до десятков C#-файлов, документации, ассетов, локализации и настроек сборки.

## Что мы можем делать здесь

В этой среде можно:

- создавать и редактировать файлы проекта;
- держать структуру папок мода;
- писать C#-код для tModLoader;
- добавлять документацию;
- запускать доступные проверки и команды;
- смотреть `git diff`;
- делать коммиты;
- готовить pull request'ы;
- постепенно развивать мод по версиям.

## Как лучше организовать работу

Рекомендуемый цикл:

1. Обсуждаем идею или задачу.
2. Формулируем маленький этап, который можно закончить за одну сессию.
3. Вносим изменения в файлы.
4. Проверяем сборку или хотя бы статические ошибки, если tModLoader недоступен.
5. Делаем коммит.
6. Оформляем pull request.
7. Переходим к следующему этапу.

## Почему не стоит писать весь мод одним сообщением

Первая рабочая версия может содержать 30–50 файлов и несколько тысяч строк кода. Обычный чат плохо подходит для такого объёма:

- легко потерять часть файлов;
- трудно исправлять уже написанное;
- неудобно отслеживать изменения;
- сложно поддерживать единую архитектуру;
- сложно возвращаться к старым версиям.

В Codex лучше работать как в обычном проекте: маленькими изменениями, с Git-историей и документацией.

## Рекомендуемые типы задач

Хорошие задачи для одной сессии:

- «Создай базовую структуру tModLoader-мода»;
- «Добавь `DroneInstance` и перечисления режимов дрона»;
- «Добавь предмет `FPVController`»;
- «Добавь регистрацию клавиш»;
- «Добавь базовый HUD»;
- «Исправь ошибку сборки из tModLoader»;
- «Добавь сетевой пакет синхронизации позиции дрона».

Слишком большие задачи лучше дробить. Например, вместо «сделай весь FPV-дрон» лучше сначала сделать структуру, потом управление, потом HUD, потом payload.

## Как давать задания Codex

Лучше писать задачу конкретно:

```text
Сделай v0.1.0 Alpha foundation для tModLoader-мода Drone Warfare.
Нужно создать базовую структуру, build.txt, description.txt, главный Mod-класс,
DroneConfig, DroneKeys, DroneSystem, DronePlayer и пустой DroneInstance.
После изменений проверь проект доступными командами, сделай коммит и PR.
```

Если есть ошибка сборки, лучше вставлять полный текст ошибки:

```text
При сборке tModLoader выдаёт ошибку:
<текст ошибки>
Исправь её, не меняя архитектуру без необходимости.
```

## Что стоит уточнять заранее

Перед реализацией игровых систем полезно заранее определить:

- версию tModLoader;
- целевую версию Terraria;
- режим игры: одиночная, мультиплеер или оба;
- клавиши управления;
- поведение персонажа во время управления дроном;
- баланс топлива и дальности;
- правила Friendly Fire;
- список payload для первой версии.

## Как использовать этот репозиторий

Этот репозиторий стоит использовать как основной источник правды:

- идеи и решения фиксировать в `Docs/`;
- готовый код держать в папке `DroneWarfare/`;
- этапы разработки держать в `ROADMAP.md`;
- изменения версий описывать в `CHANGELOG.md`;
- крупные архитектурные решения переносить в отдельные документы.

## Предлагаемый первый milestone

**v0.1.0 Alpha Foundation**:

- создать tModLoader-проект;
- добавить минимальный Mod-класс;
- добавить конфигурацию;
- добавить keybind'ы;
- добавить `DronePlayer`;
- добавить `DroneInstance`;
- добавить `FPVController`;
- убедиться, что мод появляется в списке и предмет можно получить.
